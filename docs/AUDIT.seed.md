* **Current State of BASALT**: BASALT began as Project Atlas—a single-instrument C++20 price-time priority limit order book and matching engine with a single-threaded HTTP API (`cpp-httplib`), a single-page browser dashboard, a 7-profile synthetic benchmark runner comparing a `std::map` + `std::list` + `std::unordered_map` book against a sorted-vector baseline, and an 18-test GoogleTest suite enforcing 8 book invariants.

* **Architectural Strengths**: Deterministic single-threaded matching loop, integer price-tick arithmetic (zero IEEE-754 float drift), $O(1)$ best-bid/ask lookup via cached tree iterators, $O(1)$ order cancellation via iterator map, and strict separation between the core engine library and the HTTP/UI layer.
* **Key Technical Risks & Gaps**:
1. **Single-Instrument Coupling**: `OrderBook` and `MatchingEngine` implicitly assume one anonymous instrument rather than an `InstrumentId`-keyed multi-instrument book router.

2. **No External vs. Simulated Liquidity Boundary**: Currently, every submitted order enters the internal order book directly; there is no distinction between external market observations (NSE/BSE quotes/ticks) and internal simulated orders.

3. **Missing Risk & Portfolio Accounting Layers**: Orders bypass pre-trade risk controls and execute without double-entry cash, position, average-cost, or fee accounting.

4. **Volatile In-Memory State**: Restarting the server wipes all order history, trades, and metrics; there is no persistent event log or historical OHLC storage.
